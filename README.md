# 🧌 Матюкливий гномик

Telegram-бот, інтегрований з Notion, який стежить за статусами тасок і
нагадує про дедлайни — не завжди ввічливо. Рівень токсичності зараз:
м'яко-агресивно + сарказм, без справжнього мату (легко посилити, див. нижче).

## Що вміє

- **`/register Ім'я`** — прив'язує твій Telegram до імені в колонці «Відповідальний» у Notion.
- **`/tasks`** — показує твої активні таски з кнопками для зміни статусу прямо в Telegram (записується в Notion).
- **`/newtask Назва | Дедлайн | Відповідальний | Пілон`** — створює нову таску прямо в Notion з Telegram.
- **`/report`** — загальний звіт по команді: хто і на скільки днів прострочив, з тегами.
- **`/roast`** — миттєво просоромити найгіршого боржника команди, для розваги.
- **Всі нагадування йдуть у груповий чат команди і тегають конкретну людину** (клікабельний тег, як звичайне згадування в Telegram) — див. розділ "Груповий чат і тегання" нижче.
- **Щоденний дайджест о 10:00** — особисто кожному список його тасок **на поточний тиждень** (пн–нд), окремо позначено, що вже прострочено з минулого і без дедлайну.
- **Нагадування "2 дні до дедлайну"** — спрацьовує, якщо до дедлайну рівно 2 дні, а статус досі "не почато".
- **Нагадування "1 день до дедлайну"** — спрацьовує за день до дедлайну незалежно від статусу.
- **Періодичні нагадування** (за замовчуванням раз на 3 години в робочий час) — окремо для вже **прострочених** тасок, тон стає агресивнішим що довше прострочка.
- **Двосторонній зв'язок з Notion** — таску можна створити і з Telegram, і напряму в Notion; бот про неї дізнається в обох випадках (див. розділ нижче).

## Крок 1 — База в Notion

Створи (або адаптуй наявну) базу-трекер з такими колонками:

| Назва колонки      | Тип         | Приклад значення              |
|---------------------|-------------|--------------------------------|
| Завдання            | Title       | Карусель «5 прав ВПО»          |
| Статус              | Select      | Заплановано / В роботі / На перевірці / Готово |
| Відповідальний      | Text        | Оля                             |
| Дедлайн              | Date        | 28.08.2026                     |
| Зона/пілон           | Select      | Права людини (опційно)         |

Якщо у тебе вже є база з іншими назвами колонок — не перейменовуй нічого,
просто впиши свої назви у `.env` (`NOTION_PROP_*`, див. `.env.example`).

**Важливо:** значення в колонці «Відповідальний» мають писатись однаково
(без орфографічних варіацій) — саме за цим текстом бот зіставляє людину.

**Про статус "не почато":** якщо у твоїй базі немає окремого статусу
«Не почато», а «непочату» таску позначають, наприклад, «Заплановано» —
усе ок за замовчуванням, бот саме так і вважає (`NOTION_NOT_STARTED_STATUSES`
в `.env`). Якщо у вас є явний статус «Не почато» — він теж підхопиться,
можна лишити обидва варіанти в списку.

### Додай календарний вигляд (Calendar view)

Щоб бачити всі дедлайни як календар прямо в Notion:

1. Відкрий базу-трекер → кнопка **+ Add view** (зверху, поруч із назвами вкладок).
2. Обери тип **Calendar**.
3. Коли Notion запитає, яку Date-властивість використати — вибери **Дедлайн**.
4. Готово: тепер у тебе є вкладка-календар поруч зі звичайною таблицею.
   Це чисто налаштування інтерфейсу Notion, воно не впливає на роботу бота —
   бот працює з тими самими даними незалежно від того, яким виглядом (таблиця,
   календар, дошка) ви на них дивитесь. Публічний API Notion не дозволяє
   створювати вигляди програмно, тож цей крок робиться руками один раз.

### Підключення інтеграції

1. Зайди на https://www.notion.so/my-integrations → **New integration**.
2. Назви її, наприклад, «Гномик», обери свій workspace, збережи.
3. Скопіюй **Internal Integration Secret** → це `NOTION_TOKEN`.
4. Відкрий свою базу в Notion → кнопка **···** у правому верхньому куті →
   **Connections** → підключи щойно створену інтеграцію (без цього кроку
   бот побачить базу як порожню, це найчастіша помилка).
5. Скопіюй `NOTION_DATABASE_ID` з URL бази:
   `notion.so/workspace/1a2b3c4d...?v=...` → бери частину `1a2b3c4d...`
   (32 символи до знаку `?`).

## Крок 2 — Бот у Telegram і груповий чат

1. Напиши в Telegram боту **@BotFather** → `/newbot`.
2. Назви його, наприклад, **Матюкливий гномик**, і дай username (напр. `matyuklyvyi_gnomyk_bot`).
3. Скопіюй виданий токен → це `TELEGRAM_BOT_TOKEN`.
4. Створи (або обери наявний) груповий чат команди в Telegram, додай туди бота.
5. Щоб бот міг тегати людей у групі, кожен учасник спершу пише боту `/start`
   **в приватному чаті** (це обов'язково — інакше Telegram не дозволить боту
   надсилати їй особисті нотифікації навіть у форматі тегу).
6. Дізнайся `chat_id` групи: напиши в групі будь-яке повідомлення, потім
   відкрий у браузері
   `https://api.telegram.org/bot<ТВІЙ_ТОКЕН>/getUpdates`
   і знайди `"chat":{"id": -100...}` — це значення для `TEAM_CHAT_ID` у `.env`.

Якщо `TEAM_CHAT_ID` не заповнити — бот повністю робочий, просто нагадування
йтимуть кожному особисто в приват, без тегів і без спільного огляду для команди.

---

## Крок 3 — Налаштування проєкту

```bash
cp .env.example .env
# відкрий .env і встав TELEGRAM_BOT_TOKEN, NOTION_TOKEN, NOTION_DATABASE_ID

python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt

python bot.py
```

Якщо все правильно — у консолі з'явиться `Матюкливий гномик прокинувся...`.
Тепер кожен з команди пише боту `/start`, а потім `/register Ім'я`.

## Крок 4 — Де тримати бота запущеним 24/7

Бот має весь час "слухати" Telegram і Notion, тож ноутбук не підходить —
щойно закриєш його, гномик засне. Найпростіший варіант без адміністрування
сервера — **Railway**:

1. Заведи акаунт на https://railway.app (можна через GitHub).
2. Заливаєш цю папку в свій GitHub-репозиторій.
3. У Railway: **New Project → Deploy from GitHub repo** → обираєш репозиторій.
4. У вкладці **Variables** вставляєш всі значення з твого `.env`
   (кожен рядок — окрема змінна).
5. Railway сам визначить, що це Python-проєкт, встановить залежності
   і запустить `python bot.py` (можна також явно задати команду запуску
   у **Settings → Start Command**, якщо не підхопить автоматично).
6. Готово — бот працює постійно, Railway перезапускає його при падінні.

Альтернативи, якщо Railway не підійде:
- **Render** → Background Worker (не Web Service — боту не треба відкритий порт).
- Будь-який дешевий VPS (напр. Hetzner, DigitalOcean) + `systemd`-сервіс, якщо
  хочеться повного контролю.

**Важливо:** `users.json` (реєстрація команди) зберігається на диску сервера.
На безкоштовних/дешевих тарифах диск іноді не персистентний між деплоями —
якщо після оновлення коду команда "злетіла" і треба реєструватись заново,
це нормально для MVP. Для надійнішого варіанту можна перенести зберігання
реєстрацій у саму Notion (окрема маленька база "Команда") — скажи, якщо
потрібно, допоможу переробити.

## Двосторонній зв'язок: як таски синхронізуються

**Telegram → Notion** (уже повністю працює з коробки): команда `/newtask`
створює справжню сторінку у твоїй базі Notion. Ніякої окремої "бази бота"
нема — Notion лишається єдиним джерелом правди, бот просто пише і читає з неї.

**Notion → бот** (те, що бот бачить нову/змінену таску): бот ЗАВЖДИ читає
Notion наживо, без кешу — тобто щоденний дайджест, `/tasks`, `/report`,
нагадування про дедлайни автоматично побачать будь-яку таску, додану чи
змінену прямо в Notion, під час найближчої перевірки (вони й так відбуваються
по кілька разів на день). Це вже "синхронізація" в сенсі "нічого не загубиться".

Якщо ж хочеться, щоб бот миттєво писав у чат "О, нова таска!" одразу, як
хтось додав її в Notion, а не чекав до наступної запланованої перевірки —
для цього є опційна, просунутіша частина: **вебхук від Notion**.

### Налаштування вебхука (опційно, потребує публічного URL)

Це working, але додаткове налаштування — без нього бот на 100% робочий,
просто трошки менш "миттєвий" у бік Notion → Telegram.

1. Бот має бути задеплоєний на хостингу з публічним доменом (Railway дає
   його автоматично — див. Крок 4). Знайди свій публічний URL у Railway
   (Settings → Networking → Public Networking), наприклад
   `https://matyuklyvyi-gnomyk-production.up.railway.app`.
2. Переконайся, що бот слухає порт із змінної `PORT` — Railway підставляє
   її сам, локально в `.env` лишається `PORT=8080`.
3. Зайди в Notion → **Settings → Connections** (або в самій інтеграції на
   https://www.notion.so/my-integrations → твоя інтеграція → вкладка
   **Webhooks**) → **+ Create a subscription**.
4. У полі URL встав `https://твій-домен/notion-webhook` (шлях за
   замовчуванням, налаштовується через `NOTION_WEBHOOK_PATH`).
5. Обери типи подій: `page.created` і `page.properties_updated` для бази-трекера.
6. Notion одразу надішле на цей URL один тестовий запит із `verification_token`.
   Бот залогує це значення (дивись логи Railway) великими літерами. Скопіюй
   токен і встав його як `NOTION_WEBHOOK_SECRET` у Variables на Railway,
   перезапусти сервіс.
7. Поверніся в Notion і підтверди підписку, вставивши той самий токен
   (Notion попросить це зробити в інтерфейсі підключення).
8. Готово — тепер і створення, і редагування тасок прямо в Notion миттєво
   прилітає повідомленням у ваш `TEAM_CHAT_ID`.

**Якщо щось піде не так:** вебхуки Notion — відносно нова можливість
(з'явилась протягом 2026 року) і час від часу змінюється. Якщо крок 6–7
поводиться інакше, ніж описано, — орієнтуйся на актуальний розділ
"Webhooks" в офіційній документації https://developers.notion.com/reference/webhooks,
там завжди найсвіжіша версія кроків підтвердження підписки.

---

Усі фрази гномика лежать у `messages.py`, розбиті по "тонах" залежно від
того, наскільки прострочена таска: `DUE_TODAY` → `OVERDUE_LIGHT` →
`OVERDUE_MEDIUM` → `OVERDUE_HEAVY`. Хочеш реального мату — просто редагуй
рядки в цих списках, нічого іншого міняти не треба. `SPICE_LEVEL` в `.env`
зарезервований на майбутнє, якщо захочете кілька режимів одразу (наприклад,
окремий набір фраз для "жорсткого" режиму) — це нескладно додати.

## Обмеження поточної версії (чесно попереджаю)

- Один статус "Відповідальний" на людину — якщо таску ведуть двоє, бот
  нагадає лише тому, чиє ім'я записано в Notion.
- Реєстрація («хто є хто» в Telegram) зберігається локально у `users.json`,
  не в Notion.
- Немає розпізнавання часових поясів для кожного окремого учасника —
  один `TIMEZONE` на всю команду.
- Тегання (`tg://user?id=...`) надійно працює, коли людина є учасником
  групового чату і хоч раз писала боту в приваті `/start`. Без цього
  Telegram може не показати клікабельний тег.
- Вебхук від Notion (розділ вище) — опційна й трохи "жива" (beta) частина
  API Notion; основний функціонал бота від неї не залежить.
